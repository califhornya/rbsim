CLONE-FIDELITY PROBE — RBSIM e72318e
Measured 2026-11-17. Report and all experiment programs included in the ZIP.
No production engine changes. Numbers below are measured, not estimates.

The copies are not faithful. Across 576 seeded source games and 3,123 sampled
copy points, 61 points diverged in decisions/choices in ALL THREE copy variants.
19 points changed the winner (16 distinct source games). 57 of the 576 source
games contained at least one failing checkpoint; these are correlated samples,
not an estimate of a random game's probability of failure.

Isolating one store at a time attributes 58 failing points to combat_designated
and 3 to once_per_turn_used (Pyke Returned). No seeded sampled point contained
conquer_return. A separate small constructed case confirms its known failure.

Beyond those stores: a fresh GameLoop loses cumulative units_played and
spells_cast. This is a real full-Result fidelity failure of the GS+new-loop
integration, separate from gameplay divergence. I found no additional cause
of gameplay divergence in this measured scope. That last statement is bounded
negative evidence, not proof that the rest of the card corpus is clone-safe.

2. What exactly was copied and compared

C: clone_state — gs.clone(), then GameLoop(copied_gs), with no pending loop
work at the sampled boundary. Native code: state.py:245; loop.py:458.

D: deepcopy_state — copy.deepcopy((gs, anchor_card), memo), memo mapping each
current agent to None, then a fresh GameLoop. This is the graph-copy primitive
used in _declare_choices, loop.py:719-725. The anchor's aliases are copied in
the same operation as the state.

L: deepcopy_loop — copy.deepcopy((loop, EffectContext), agent-detachment memo),
then equivalent agents. This extra control preserves loop counters and context;
its graph shape is the second declaration copy at loop.py:853-858. It uses the
same agent detachment as D; the actual nested declaration's empty memo and
ModeAsker graph are not an end-to-end tested service/recorder integration.

I did NOT play a declaration's _dry_run/ghost-restored board as though it were
a live game. Those flags intentionally change execution. C and D test the
copy primitives under full live continuation; L separates lost loop history
from bad state-object references. Actual declarations still run normally
inside every reference and copied continuation.

Original and copy both get fresh policies of the same classes, with each
RandomAgent's exact getstate()/setstate() transferred; the game RNG is copied.
Policy caches are reset symmetrically. All 9,369 baseline pairs have identical
starting game/agent RNG fingerprints. This does not test transplanting a
historical agent cache onto a new gs identity.

The reference is an OS fork that returns to the ORIGINAL live Python stack,
not another serialized copy. It runs native start()/main/showdown/chain code.
Each copy and control runs in a different fork, preventing speculative games
from altering the parent's RNG, registry objects or allocation history.

Native loop bodies are extracted with AST for resumable main/chain/showdown
tails. The live local main-action count and priority pass/round counters are
retained. At EVERY checkpoint, running that adapter on the UNCOPIED original
graph matches the native reference: zero invalid adapters, zero exceptions.
No rules are reimplemented in the adapter. The largest observed main-action
budget upper bound was 18, far below the 200 cap; retaining the local offset
therefore cannot hide an observed native resume_to_completion cap difference.

Fresh-loop guard: no pending_move, staged_showdowns, pending triggers, task
depth, trigger flush, all-pass resolution, active declaration/replay/choice
slot, ghost board, resolving item, choose_many or discard frame. A main point
also has no chain or active showdown. SD/reaction points preserve explicit
priority-window locals: SD must come directly from main PASS -> flush move;
reaction must come directly from a SPELL in that SD. Arbitrary nested effect
resolution, other call paths and pending tasks are excluded, not assumed safe.

Sampling: up to eight points/game. Main points are after an action, on each
seat's second-or-later own turn, in early/late buckets; a current-turn id-store
use gets an extra slot. One combat SD and one eligible reaction are sampled,
with deciding seat alternated by replica. See Audit.visit/checkpoint_context.

Compared: every returned action tuple, its window/seat/turn and direct card
label; engine target/mode/optional choices including weak identity labels;
winner, turns, final points; full Result; full terminal model-graph hash;
ending game and policy RNG. Alias relationships, zone/deck order and dynamic
card/unit fields are retained in the graph. Random UUID4 spelling and raw
addresses are excluded. The three known integer-id stores are inventoried
separately and omitted from the terminal hash: their raw integer differences
must not be mistaken for an additional cause. No trace retains live units.

6. What beyond the three stores did and did not cause a failure

Confirmed additional full-Result cause (HIGH confidence): fresh-loop cumulative
history reset. It affects C/D and is independently reproduced without a live
id-keyed store. L is the counter-preserving control. No change to engine code
is needed to observe this; no claim that this changes winner-based rollouts.

No additional gameplay cause found (HIGH confidence for these 61 cases;
LIMITED confidence as a corpus-wide absence claim): every baseline behavioral
failure is eliminated by one initial store rebase and L has the same 61. Thus
there is no unexplained gameplay divergence in this data. This does not prove
that discarded transient loop state, agent caches, shared printed card data,
declaration ghost-board restoration, or other handlers are universally safe.

The base_agent _adds_now id(gs) cache is not a fourth tested persistent
GameState identity store. Cache contents are reset on BOTH sides and the
requested policies are RNG-aligned; transplanting live policy caches is out
of scope. Random uuid4 spelling is not a game decision; target aliases and
model-graph relationships are compared independently of those strings.

Confidence and limits:
- Counts, 61 failing checkpoints, 19 winner changes, replay validity: HIGH,
  measured with raw traces, controls and assertions.
- Attribution of 58 combat / 3 Pyke cases: HIGH, selective single-store
  intervention restores each of the 183 corresponding path continuations.
- conquer_return failure: HIGH for M7, NOT VERIFIED in the seeded sample.
- No further gameplay causes in the chosen scope: HIGH for this dataset,
  no universal claim about cards/windows not reached.
- Real declaration-UI/recorder/SQLite copying, learned/search agents, network
  agents, arbitrary mid-resolution/queued-work cloning, every legal alternative
  action and every corpus card: NOT VERIFIED by this experiment.
- This is policy continuation fidelity, not another counterfactual legal-action
  probe and not an official-rules adjudication. It does not decide whether the
  original continuation itself follows all rules.

7. Repeatable commands and delivery

From the unpacked clone_fidelity_audit directory, on Linux:
  export RBSIM_REPO=/absolute/path/to/rbsim
  export RBSIM_CLONE_OUT="$PWD/fresh_exact"
  python exact_trace.py --repeats 4 --workers 6
  python analyse.py fresh_exact
  python attribute.py fresh_exact --output fresh_attribution
  python minimal.py
For the earlier confirmation pass use probe.py with a separate output directory.
Scripts need the repo's normal dependencies; no torch or GPU. Tests were not
modified and no engine fixes were applied. Detailed setup, dataset extraction,
commands and checksums are in README.txt and SHA256SUMS.txt in the ZIP.
