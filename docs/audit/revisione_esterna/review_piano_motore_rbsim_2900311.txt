## Where the plan breaks down

1. **It puts two confirmed engine defects behind a large structural PR.** On current `main`, Black Market becomes usable a second time in a clone, and a cloned combatant loses its designation. The common cause is persisted `id()` keys that still refer to the original objects after copying. Separately, I replayed the Jarvan IV and Detonation Amplifier case. The gear deploys and draws a card, yet the showdown step returns `noop` because hand size stays at one. A live showdown counts that as a pass. Both defects survive a move-only split and a public wrapper around the same methods. I’d capture them in Phase 0 and fix them in separate, explicitly behavior-changing commits before moving code. **Measured on `main`.** [Clone implementation](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/state.py#L245) · [Showdown outcome](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/loop.py#L7839)

2. **The proposed trace is neither deterministic as supplied nor complete enough to be the sole gate.** I ran `python -m scripts.trace_game` twice with Zed vs. Shen, `--aiA random --aiB random --seed 42`, and `PYTHONHASHSEED=0`. The first actions differed and the winners were **B in 20 turns** and **A in 15 turns**. The CLI builds the game without agents and installs them afterward, bypassing the factory’s per-seat RNG seeding. It also logs four outer decision callbacks. Target and mode choices run through a separate path inside `GameLoop`. A hash can detect a difference in what was recorded, but locating the first divergent decision requires retaining the event records or rerunning the pinned reference. I’d seed the actual agents, capture structured events at declaration and resolution, and verify that enabling tracing leaves the seeded game unchanged. One factual correction for Phase 0: the current fixture already has **28 games, including eight Kai’Sa/Kennen games**. **Measured by rerunning the tracer and counting fixture keys.** [Phase 0](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L199) · [Tracer setup](https://github.com/califhornya/rbsim/blob/2900311/scripts/trace_game.py#L174) · [Factory seeding](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/game_factory.py#L182) · [Golden matchups](https://github.com/califhornya/rbsim/blob/2900311/tests/test_golden_games.py#L45)

3. **“Each operation performs the complete sequence” is too broad for Riftbound timing.** The proposed `choose unit → record choice` operation sounds sensible until a spell declares targets on a copy. The live `_put_on_chain` deduplicates those targets, applies Deflect and chosen triggers at declaration, and marks them as accounted for during resolution. A selection made to pay a cost also has a different contract from declaring a target. Likewise, `_kill_unit` removes the selected units before routing their deaths together by location. Replacing that with one complete `kill` call per unit can change what replacements and triggers see. Define the contract by timing and batch boundaries before choosing API names or committing to **20–30 operations**. Co-occurrence counts help locate callers. They cannot establish which sequences are equivalent. **High confidence from the code. The proposed API does not exist yet, so its exact impact is unverified.** [Phase 2](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L255) · [Declaration](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/loop.py#L651) · [Death batching](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/effects.py#L4505)

4. **The ratchet can go green without creating a real boundary.** I reproduced Appendix B’s **89 names and 428 attribute accesses** in `effects.py`. Counting direct `ctx.loop` and local `loop` receivers without its same-name exclusion gives **94 names and 447 accesses**. The exclusion drops **19 real accesses** across five names, including `_play_token`, because `effects.py` also defines functions with those names. Renaming a private method public can drop the count while preserving the same dependency. The mixin check has a separate blind spot: in a small Python probe, adding a mixin with a duplicate `choose` left `dir()` identical while changing the implementation called. Use the counts as diagnostics. Gate on explicit dependency boundaries and check method ownership and duplicates across the MRO if mixins are used. **Measured AST counts and Python probe.** [Phase 1 check](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L228) · [Appendix B](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L351)

5. **The effects API and the search API are different design problems.** Phase 3 gives AI and legality a single “same method” bullet. Search needs to advance a decision, retain priority or focus when appropriate, and preserve pending work across a copy. Effect handlers need rule operations with defined timing. A public spelling for `_apply_action` solves neither. I’d define the search contract early and migrate a single caller before committing to the package split. Include a targeted test that proves neural replay actually reaches and replays a nested choice. Twenty seeded games with an untrained net give no guarantee that branch was exercised. A Windows constraint on process `fork` also says nothing about copying simulator state within one process. **High confidence in the distinction. Neural runtime parity is unverified here.** [Phase 3](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L278) · [Search replay cursor](https://github.com/califhornya/rbsim/blob/2900311/riftbound/ai/net_mcts.py#L184) · [Resume entry point](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/loop.py#L8135)

6. **Phase 4 assumes the shared helpers are already neutral.** Of its ten named private imports, **six directly access the loop or its state**. `_return_gear` removes gear, fires a leaves-board trigger, and can add a card to hand. Moving it into `targeting.py` relocates an engine mutation. Extract the pure predicates where they exist and give mutations an engine owner. The **5% speed gate** has a similar scope problem: total traced game time combines simulation, formatting, and output. Benchmark uninstrumented game throughput, clone time, and search separately with paired seeds and repeated runs. **Helper count measured. Performance impact unmeasured.** [Phase 4](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L293) · [Gear removal helper](https://github.com/califhornya/rbsim/blob/2900311/riftbound/core/effects.py#L480) · [Speed criterion](https://github.com/califhornya/rbsim/blob/2900311/docs/PIANO_MOTORE.md#L141)

My revision to the order would be **deterministic decision traces and focused probes → clone and action-outcome fixes → one shared transition used by a live caller and a search caller → effect extraction family by family**. Keep the staged PRs and the frozen goldens. Make the acceptance criteria about what the engine does at those boundaries, with file length and underscore counts as secondary signals.
