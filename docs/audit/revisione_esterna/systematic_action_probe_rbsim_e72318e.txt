HOW THE GAMES WERE SELECTED — MEASURED

The six files under riftbound/data/decks/ are competitive_evelynn,
competitive_kaisa, competitive_kennen, competitive_khazix, precon_shen and
precon_zed. I used all 36 ordered pairs, including mirrors, and all four ordered
agent pairs: random/random, random/simple_trade, simple_trade/random and
simple_trade/simple_trade. Four repetitions per combination give 576 games.
Each deck occupies each seat in 96 games; each agent pairing has 144 games.
No sideboarding. The factory's normal max_turns=40 and battlefield selection
apply. Four game seeds per combination are derived, in sorted deck order, from
random.Random(2026111701).randrange(1 << 30); the script contains the exact product
iteration. The random agents retain the factory's seeded RNG for each seat.

I first used replacement observer agents. A no-audit control exposed four
different game outcomes caused by that observer arrangement itself. I discarded
that run for the final measurements and reran all 576 games by decorating methods
on the original agents. The final run agrees with an uninstrumented replay in
576/576 comparisons of winner, turns, points_A and points_B. This control does
not prove complete final-state or decision-trace identity; those were not
compared. Preliminary-run counts are not pooled into the numbers above.

THE ORACLE AND ITS LIMITS

The independent before/after snapshot walks the model object graph, including
GameState, players, cards, units, battlefields, chain, counters, dynamic model
fields, pending triggers, RNG state and units_played/spells_cast. Stable labels
are assigned to the same objects within a trial, so swapping equal-looking
cards or units is visible. Object references are retained during each trial to
prevent Python address reuse from corrupting that comparison. The engine's
_action_fingerprint is used only to reproduce its own reported result, never as
the independent progress oracle.

Excluded: agents and their caches, recorder/journal/chooser infrastructure,
the duplicate Player.battlefields reference injected by GameLoop, Card.uuid
(fresh-copy bookkeeping), Card.effects (printed immutable text), and absent
versus empty/default private Card flags. All detected failures also have a
concrete board, zone or pending_move delta, rather than only a cache change.

Each clone copies GameState and the live loop's pending work/control context
in one deepcopy graph. In particular _pending_triggers, _task_depth, _flushing,
_all_pass and declaration/replay context are retained. Constructing a fresh
GameLoop from a bare gs.clone() would reset this context and misrepresent
decisions nested inside tasks. The exact copied-field list is in probe.py.
Agents are removed from the clones, so later responses default to PASS and
subchoices use the engine's default policies. This is one continuation per
offered action, not enumeration of all target, optional, mode, or reaction
continuations. Existing id()-key clone defects are preserved; this probe does
not repair them. The minimized failures also reproduce directly without a
clone, so those failures do not depend on those known identity defects.

For main actions, _apply_action returns None. Its effective outcome is the
_run_main_actions fingerprint guard, including its special ended_move exception
and passive recomputation. For reactions I record both _reaction_step's result
and the result actually consumed after the caller's trigger flush and chain
growth override (7601–7605). For showdown I compare immediately after
_showdown_step, before the caller's later _open_combat. acted and kept both mean
an applied action for this progress check; priority correctness between them
is a separate property, not established here.

PASS is intentionally not required to mutate the model. Main PASS can finish
pending_move, run its showdown and continue main; reaction/showdown PASS affects
the caller's local priority/pass counters. Those are valid PASS semantics, not
false no-ops. Every PASS offer was still cloned and exercised by that window's
driver semantics. The audit also flags a non-PASS offer that is unchanged and
refused as noop; none occurred in the final seeded run.

FINDING A — PENDING MOVE SWALLOWS A LEGAL ABILITY

High confidence, measured in seeded games and minimized directly.

_apply_action at loop.py:5500–5503 intercepts every non-joining action while a
Standard Move is pending, flushes that move and returns before executing the
chosen action. That is intentional for an ordinary main-phase move declaration.
But legality.py's reaction/showdown menus still offer activated abilities in
nested windows with pending_move present. The main-only menu filter at
legality.py:162–166 does not protect these windows.

_use_ability_now (6774–6777) then compares a partial fingerprint. Clearing
pending_move and establishing battlefield control are absent from it. If no
counted quantity changes, it reports False and the step returns noop, even
though a held move was completed or its marker was consumed. Gold and Seal
remain unspent; Kai'Sa remains ready and adds no spell power. This is not a
successful activation mislabeled: the requested activation never runs.

During an already active showdown, _flush_pending_move clears the marker and
_run_showdown immediately returns because showdown_active is true (7741–7742).
That alone can produce the discrepancy. Outside that situation, a move's
showdown can establish control without changing the fingerprint, particularly
when the battlefield already scored this turn.

Minimal reproduction recipes (all use an action obtained from legal_actions):

1. Reaction, Gold or Seal of Discord: ready Traveling Merchant in A's base,
   one discardable hand card, the ready gear in base, and a battlefield marked
   already scored by A this turn. Standard Move Merchant to that battlefield.
   Its on_move trigger opens a reaction window before pending_move is flushed.
   Choose the offered gear ability. Result noop; pending_move clears and the
   battlefield can become held by A; the gear is not used. See
   reproduce.py:pending_reaction_case('Gold' or 'Seal of Discord').
2. Showdown, Gold or Kai'Sa: A has a ready Gold or ready Kai'Sa legend, B is
   active, both players have a unit at BF0, showdown_active=True, BF0 is the
   showdown, and pending_move=(0,'B'). Choose A's offered ABILITY. Result noop;
   pending_move becomes None; the source remains ready/unspent. These conditions
   are reduced from actual sampled nested windows. See pending_showdown_case.
3. Reaction, Kai'Sa: same reduced showdown state, with an open chain; ask
   legal_actions(REACTION,'A') and apply that ABILITY. Same result. The original
   sampled state had a real chain; the small reproduction needs only an open
   chain item because it never resolves it.

Impact: noop is counted as a pass by _run_chain (7606–7617) and _run_showdown
(7792–7798), so a real state transition can advance priority/pass accounting or
end a window. When the move flush changes something the fingerprint does count,
an interrupted activation can instead report success. This probe's counts are
only contradictions between progress and acknowledgment, not a count of every
swallowed activation. They do not estimate match win-rate impact.

FINDING B — DRAWING GEAR FAILS THE HAND-SHRINK SUCCESS TEST

High confidence, measured in focused fixtures and direct minimal reproductions.
Not reached by any GEAR offer in the final sampled reaction/showdown menus.

Jarvan IV Martial Paragon grants ACTION to friendly DEPLOY gear. In a showdown
with Jarvan in A's base, an A/B unit at BF0, sufficient normal runes and the gear
in hand, legal_actions offers GEAR. _showdown_step (7843–7846) executes it but
requires len(hand) to decrease before returning acted.

Detonation Amplifier: hand [Amplifier] -> [Drawn card]. It deploys, costs energy,
kills the available friendly 1-Might sacrifice and draws one; the equal final
hand size makes the step return noop. Reproduction uses six Fury runes.

The Good Stuff: hand [The Good Stuff] -> three drawn cards. It deploys and pays
its cost, then the default on-play resolution draws three after the attempted
discard. The final hand is larger, so the step returns noop. Reproduction uses
six Chaos runes. There is no available card to discard after the gear leaves
the one-card hand; the engine proceeds with the remaining instructions. This
test demonstrates the implementation's outcome acknowledgment, not a separate
rules judgment about that card's effect parsing.

Both are reproduce.py:gear_case(name). The same hand-shrink inference exists in
_reaction_step at 7641–7644, but I did not find a reaction-speed gear failure in
the scanned fixtures. Do not promote that static risk into a measured failure.

Impact: the gear and its effects happen, but the showdown caller counts it as
a pass. A pre-existing consecutive pass can therefore close the window after
an actual play. The probe does not simulate every subsequent priority choice.

FINDING C — A FREE CHAMPION HIDE ENDS MAIN AS A FALSE NO-OP

High confidence, direct measured regression outside the six-deck trajectory.

Teemo Scout is a registry Champion with HIDDEN. Put it in A's Champion Zone,
give A control of a battlefield, and set the real state produced by Guerilla
Warfare's free_hide_this_turn effect. legal_actions offers HIDE('champion', BF0).
_hide_card returns True, sets champion_A_deployed and adds a facedown card.
Hand size, resources, unit counts and every other fingerprint quantity stay
unchanged. _apply_action discards the helper's Boolean; the main guard treats
the successful hide as a no-op and ends the action phase.

reproduce.py:free_champion_hide_case checks both the clone-based result and the
actual _run_main_actions: the agent is asked exactly once, although its second
response would have been PASS. Thus main ends at the guard before another
decision. The generalized risk concerns other free HIDDEN champion hides too;
only Teemo Scout is claimed as the additional measured regression here.

WHY THE EXISTING LEGALITY TEST DID NOT ESTABLISH THIS PROPERTY

Measured from tests/test_legality.py: _GAMES contains three games. Its
_ProbeLoop hooks main _apply_action, compares the engine's own fingerprint,
and explicitly exempts ABILITY from the progress requirement (around 89–92).
It does not observe all three window callbacks with an independent model diff.
Therefore that test cannot rule out the failures above. This is a statement
about its test oracle and scope, not a claim that the whole suite lacks tests
of the affected cards.

LIMITS / CONFIDENCE

High: measured counts, the eight minimized failure variants, code locations,
and the concrete state deltas in the attached records. All minimal reproduction
assertions passed on the unmodified code. No match-impact percentage is estimated.

Moderate: 'no other mismatches' applies only to the sampled menus and selected
default continuation. It says nothing about unseen deck/board combinations,
sideboards, different target choices, training agents, every handler branch,
or actions legality fails to offer. In particular the seeded games offered no
GEAR actions in reaction or showdown; the corpus fixtures close that specific
coverage hole only partially. The 613-card-fixture scan is not 1,098 fully tested
cards: it selectively exercises gear plays, fast unit plays and activated unit
sources under one constructed board. The 69 gear-ability checks are another
single-board supplement, not exhaustive effect coverage.

This property also cannot prove an effect obeys official rules: an incorrectly
applied effect can still change state and return acted consistently. It does
not solve cloning identities, serialization, determinism under arbitrary
policies, event ordering, or a complete legality soundness/completeness proof.

The corrective design implied by the evidence is an explicit application
result from the execution path (applied, rejected, or ended-pending-move), with
explicit priority/focus disposition. Card helpers should propagate that result;
callers should consume it instead of testing net hand size, body counts or a
partial fingerprint. Preserve a separate loop-termination guard if needed.
I did not implement that change or regenerate any goldens.
